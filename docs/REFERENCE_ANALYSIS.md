# مراجعة الأرشيف المرجعي «الصراف.zip» / Architecture audit

هذه مراجعة تاريخية للأرشيف في مرحلة سابقة. الأرشيف ليس ضمن المستودع ولم يُعد فحصه أثناء تحديث دورة حياة واتساب. وصف المحرك والإرسال الحالي موثق في [README.md](../README.md)؛ الفقرات أدناه التي تصف المشاركة الأصلية تسجل قرار تلك المرحلة، ولا تصف جميع المسارات الحالية.

## نتائج موثقة من الملفات المرفقة (21 أكتوبر 2026)

- الحزمة المرفقة أرشيف يفكّك تطبيق Android مبنيًا باستخدام Flutter، **ليست مشروع Flutter الأصلي**. يحتوي على 24,181 مدخلة، بينها 23,154 ملف Smali، ولا يحتوي على ملفات `.dart` أو `.so` أو قاعدة بيانات `.db`/`.sqlite`.
- المكوّن المحلي الخاص بالتطبيق يظهر باسم `com.hologco.exchanger.MainActivity` داخل `classes2.dex/`، ويحتوي على `MethodChannel` لأوامر `pickDirectory`, `listFilesFromUri`, `copyFileToDirectory`, `copyUriToFile`.
- توجد مكتبات Firebase (Auth/Firestore/Storage)، وأدوات `flutter_inappwebview_android` ومدير الملفات. وجود المكتبات لا يثبت طريقة استعمالها في الكود الأصلي.
- تظهر في أصول Flutter أسماء صور لأقسام العملات، الصرافة، إرسال/استقبال التحويلات، السندات، الحسابات، التقارير والنسخ الاحتياطي، لكن الرسومات ليست منطقًا برمجيًا موثوقًا، ولم تُنقل إلى قطفة.
- الملف لا يتيح إعادة بناء الخوارزميات الأصلية أو شاشات Flutter كاملة؛ وبالتالي لا يجوز ادعاء نسخ المعادلات أو العمل المحاسبي بنسبة 100% منه.

## القرار الهندسي

- حفاظًا على تصميم قطفة، لم تُنسخ سمات Flutter ولا الصور ولا المكونات المترجمة أو بيانات التطبيق المرجعي.
- أُضيفت نسخة أصلية مستقلة من دفتر صرف العملات والحوالات وتحويلات الصندوق والبنك وسجل قيود مزدوجة إلى نموذج أحداث قطفة (`IndexedDB`)، دون إنشاء قاعدة ثانية أو تغيير أسماء بيانات العملاء.
- تتم كل عملية عبر نوع حدث مستقل: `money.exchange`, `remittance.issue`, `remittance.settle`, `fund.transfer`, `cash.open`؛ وأُلحق العرض بلوحة قطفة وسجلها الموحد.
- كل مبلغ يُحسب بوحدات العملة الأصغر ويُراجع اتزان المدين والدائن **لكل عملة على حدة**. فروق التقييم والحسابات البنكية الحقيقية لا تُحسب تلقائيًا، لذلك لا يصح اعتبار التقارير قوائم مالية مدققة.
- شاشة واتساب تعرض واجهة QR/كود فقط إذا استطاع WhatsApp Web توفيره داخل WebView. يتم استخدام `evaluateJavascript` لقراءة حالة شاشة الربط فقط دون قراءة المحادثات أو نسخ ملفات تعريف الارتباط إلى الخادم. دعم واتساب لهذه الطريقة غير مضمون ويمكنه تغيير DOM أو رفض WebView في أي وقت.
- إرسال ملفات PDF **مشاركة أصلية تتطلب تأكيد المستخدم داخل واتساب**. لا يوجد API رسمي في واتساب الاستهلاكي يسمح بالإرسال المخفي الآلي بدون موافقة/خدمة مستقلة؛ لذا لم نضع آلية خفية غير قابلة للاختبار أو نعرضها بوصفها وظيفة ناجحة.

## أمان وقيود

- لم يُنفذ أي برنامج من «الصراف.zip»، ولم تُستخدم بياناته أو أي شهادات أو رموز مضمنة في حزمة قطفة.
- النسخ الاحتياطية JSON الخاصة بقطفة غير مشفرة؛ الحفظ إلى Google Drive يتم باختيار المستخدم لوجهته من نظام أندرويد، وليس مزامنة سحابية خلفية.
- `users.json` العام واستخدام GitHub المجاني يصلحان للاختبارات أو الترخيص البسيط فقط، ولا يوفران منعًا فوريًا للاستخدام غير المرخص عند العمل دون إنترنت.
- يتطلب تسليم تجاري التأكد من تطابق المستندات المحاسبية مع واقع المحل وبيانات العملات، إضافة إلى اختبار واجهات واتساب على هاتف فعلي.
