# قطفة Qatfah — النظام المحاسبي للتجار في اليمن

**حالة الإصدار: V2 Prototype / مُعدّ للنشر والاختبار على GitHub، وغير معتمد للإنتاج.**

يحوي هذا الأرشيف مشروع قطفة المتكامل *من حيث هيكل التطبيقات والوحدات المحلية* وليس ترخيص تشغيل خدمة خارجية. وافق المالك على رفع هذه النسخة إلى GitHub للتطوير والاختبار رغم أن خدمات Google Drive وWhatsApp Web وخادم HTTPS لم تُربط تشغيليًا بعد. التجارب على الطرف الثالث تمت بمحاكاة اتصال Google، وليست تفويضًا حيًا بحساب حقيقي.

## المنجز والقابل للتجربة محليًا

- تطبيق العميل `com.qatfah.accounting`، وتطبيق المدير `com.qatfah.admin`، وموقع ويب متجاوب، وقائمة هاتف بتسعير وإحصاءات ومؤشرات ساعة واتصال الخادم وواتساب.
- نموذج **فاتورة بيع/شراء مطابق لفكرة المرجع**: اختيار العميل أو إضافته فورًا، مسح باركود بكاميرا مدعومة أو كتابة رقم، اختيار أصناف أو تسجيلها تلقائيًا، عدة بنود، كميات وأسعار، مدفوع وآجل، حفظ محلي، وتصحيح مع سجل مراجعة.
- قائمة عملاء وموردين مشتركة بجميع الأقسام مع مفتاح **اليمن +967**، بيانات الاتصال والعنوان، ونظام حسابات «عليه» (مستحق على العميل للمحل) و«له» (مستحق للعميل أو المورد على المحل)، ورصيد افتتاحي لكل عملة، وكشف حساب بفترة وتاريخ ورصيد سابق ونهائي.
- إدارة أصناف وأسعار مستقلة للعملات **YER, USD, SAR**؛ لا تُجمع عملات مختلفة ولا يتم تحويلها تلقائيًا دون سعر صرف.
- تقرير مبيعات اليوم وفواتير الفترة والتقارير المجمعة يوميًا وشهريًا وسنويًا، وحركة الصندوق لكل عملة، وسندات قبض وصرف، ومصروفات.
- فواتير PDF **A5 بالعرض** بجداول متعددة الصفحات، وشعار واسم المحل وعنوانه وبياناته وملخص المدفوع والمتبقي؛ وكشوف حساب وتقارير PDF بطباعة ومشاركة أو تنزيل على الجهاز.
- البيانات المحلية عبر IndexedDB، وتزامن الأحداث مع خادم خاص عند الاتصال؛ خادم Node/SQLite لديه إدارة مشتركين وحماية كلمات مرور بـ scrypt وفصل بيانات المؤسسات. النسخ المحلية مشفرة بكلمة مرور AES-GCM عبر Web Crypto.
- Google Drive: كود ربط OAuth خاص لكل محل عبر خادم HTTPS، مع **حفظ رموز الوصول مشفرة** على الخادم، ومجلد `Qatfah_Backup` للنسخ المشفرة، وقائمة استعادة؛ **لم يتم تفويض حساب Google فعلي**.
- WhatsApp Web: خدمة **اختيارية غير رسمية** على الخادم لاستلام رمز QR أو رمز الاقتران ثم إرسال PDF من جلسة المتجر المرتبطة دون فتح واتساب على الهاتف؛ **لم تُقرن جلسة واتساب حقيقية**، وقد تتوقف مع تحديثات الخدمة. في غياب الاتصال يقتصر الأمر على المشاركة اليدوية.
- ملفات Capacitor وأيقونات التطبيقات وWorkflow GitHub Actions لبناء APK Debug لكل نسخة **بعد النشر لاحقًا**؛ لم يُنشأ أو يُختبر APK لهذه النسخة V2.

## فحوص تحققت بالفعل

- `npm test`: 10 اختبارات ناجحة لحسابات المدين والدائن، العملات الثلاث، المدفوع الجزئي، سجل التصحيحات، التاريخ التجاري في اليمن، إدارة المستخدمين، عزل مزامنة المؤسسات، مسارات Google OAuth والنسخ *بـ Google API mock*، ومنع واتساب غير المربوط.
- تجربة متصفح Chromium بمقاس هاتف مع **تخزين اختباري في الذاكرة**: العميل +967، تحرير فاتورة وقيم الدفع، إضافة صنف تلقائيًا، تصحيح مستند، كشف الرصيد والتقرير اليومي، دون أخطاء JavaScript؛ هذا ليس اختبار IndexedDB أصليًا أو شبكة خارجية حيّة.
- توليد ومعاينة PDF من المتصفح، وتأكيد مقاس A5 أفقي صفحة واحدة في المثال.

## حدود لازمة قبل أن يصبح جاهزًا للزبائن

1. إعداد **HTTPS API** على خادم يملكه المشروع، وتوصيله بتطبيقَي العميل والمدير، واختبار التسجيل والفصل بين الشركات والنسخ الحقيقية بين هاتفين.
2. إعداد بيانات **Google Cloud OAuth**: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, ومفتاح الخادم `QATFAH_GOOGLE_TOKEN_KEY`، ثم إجراء تفويض حقيقي على أندرويد والويب وتجربة النسخ والاستعادة.
3. تفعيل وتسجيل جلسة WhatsApp Web على الخادم (`QATFAH_WHATSAPP_ENABLED=true`) وتجربة إرسال PDF إلى رقم تجريبي، مع إدراك أن الربط غير رسمي. للاستقرار التجاري، دراسة **WhatsApp Business Platform** الرسمي وسياساته.
4. بناء APK بنسخة هذه الملفات باستخدام GitHub Actions وفحص التثبيت والكاميرا والملفات والأذونات والمشاركة ووضع عدم الاتصال على هاتف أندرويد حقيقي؛ استخدام توقيع إنتاجي مستقل لاحقًا.
5. مراجعة مالية وأمنية تتناول تعارض التزامن من أجهزة متعددة، وإدارة الصلاحيات، والنسخ الاحتياطي المستمر، والمعالجة الضريبية والمخزون وتكلفة البضاعة والدفتر مزدوج القيد. **صافي الإيراد في التقارير تقديري، لا يمثل ربحًا محاسبيًا نهائيًا.**

scripts/prep-capacitor.mjs    تحضير حزمة كل تطبيق APK

### التهيئة

لا تُوضع بيانات Google OAuth أو WhatsApp أو حسابات العملاء أو رموز الدخول في مستودع عام أو ملفات JavaScript المنشورة. الملفات `server/.env.example` والقيم الافتراضية فقط أمثلة. يلزم توفير الأسرار عبر خادم خاص ومخزن أسرار آمن، وربط `QATFAH_API_BASE` بعنوان HTTPS الحقيقي، وبعدها اختبار الوظائف الحية قبل النشر على GitHub أو توزيع APK للعملاء.

**تنبيه:** `users.json` مجرد ملف توضيحي بدون حسابات أو كلمات مرور؛ السجلات الصحيحة تحفظ على خادم SQLite الخاص.


### ملاحظة حول الصور وأيقونات أندرويد في المستودع
بما أن نشر ملفات المصدر تم عبر ربط GitHub النصّي، وُضعت صور الشعار الرسمية داخل `assets/encoded/*.b64`، ويعيد `node scripts/restore-assets.mjs` إنشاء صور PNG اللازمة للموقع وتطبيقَي أندرويد أثناء البناء؛ تُولَّد أيقونات Android بالصور الأصلية باستخدام Pillow. هذا إجراء حزم للمصدر، وليس تغييرًا للهوية.
